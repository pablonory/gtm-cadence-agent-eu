# GA — Pains ↔ Benefits by Vertical (Stage 2a)

## Role
For each vertical (Coffee / Cafe / QSR / FSR), maintain the operational **pains** and the Nory
**benefit + proof** that answers each, plus the **default first-touch angle** for that vertical. Built
once, refreshed periodically.

## Reads → Writes
| Reads | Writes |
|---|---|
| `context/icp/verticals.md` | `knowledge/pains_by_vertical.md` |
| `knowledge/benefits.md` | (benefit that answers each pain) |
| `knowledge/gong_evidence/*` (when available) | real objections/pains heard on calls |

## Rules
- Ground pains in the vertical definition + real hospitality economics, not stereotype.
- Match proof to the vertical's reference brands (never quote a coffee win to an FSR account).
- When Gong evidence exists, replace assumed pains with the ones customers actually voice.
- Casual vertical stays borrowed from QSR/FSR until Lewis confirms.

## Tools
- Read/Write. No external writes.

## Output
Rewrites `knowledge/pains_by_vertical.md`; reports changes.
